## 링크·URL 수용 기준

- 시작 깊이 0, 실제 최단 링크 거리 최대 8. 설계 층별 개수는 1·4·7·7·7·6·6·6·4입니다.
- 깊이 5~8 페이지≥12(설계 22), 정확히 깊이 8 페이지≥4(설계 4).
- 깊이 6~8 양성≥8·정상≥4. 설계상 각각 22·11요소이며 실제 BFS로 확인합니다.
- 링크는 목록→관련 자료→후속 기록으로 이어집니다. 순환·이전/다음·중복 발견을 포함하고 검색은 해당 목록 안에서만 수행합니다.
- 지연 생성 a[href]로만 발견되는 페이지와 프레임 내부 링크로만 발견되는 페이지를 포함합니다. 공통 메뉴·푸터·프레임 링크를 포함한 전체 간선으로 독립 level-BFS를 수행합니다.
- 시작 URL과 링크의 raw 후보≤120. URL 해석 후 쿼리 순서·fragment를 유지한 유일 URL로 셉니다. href 원문은 별도 보존합니다.
- 동일 pathname의 쿼리별 다른 콘텐츠≥6, 순서만 다른 동일 콘텐츠 URL 쌍≥6, fragment 변형 링크≥10.
- 상대·../·루트 기준·같은 출처 절대 주소를 혼합합니다. 배포 접두 경로도 유지합니다.
- 쿼리 값은 다른 콘텐츠로 보존하고 순서·fragment는 논리적 중복으로 구분합니다. 방문 정책과 findings 중복 판정은 별개입니다.
- URL·페이지네이션은 유한합니다. 정답/전체 URL 목록을 대상에 노출하거나 정답 목록을 BFS seed로 사용하지 않습니다.

## 동적 DOM·관찰

- 최소 6개 페이지에 500·1,500·2,800ms 갱신을 분산합니다. 노드 삽입·Text Node 수정·스타일/클래스 확정·로딩 교체·프레임 삽입을 섞습니다.
- 별도 최소 2개 페이지에 3,000~4,200ms의 200ms 간격 갱신을 두고 마지막에 최종 정답을 확정합니다. 이후 무한 갱신·타이머는 없습니다.
- 시간 원점은 각 탐지 대상 최상위 문서의 DOMContentLoaded입니다. 위젯은 해당 루트 시계를 공유하고 lab/dashboard 호스트는 제외합니다.
- 최소 3,500ms·안정 300ms·최대 5,000ms의 관찰 조건으로 예정/실제 갱신·안정 시점을 측정합니다. 3.5초만 기다리면 늦은 사례가 수집된다고 가정하지 않습니다.
- maxInjectionDelayMs=4200과 사례별 delayMs를 실제 확정 시각에 맞춥니다. 기존 검증실의 최종 DOM 대기와 크롤러의 안정화 관찰 검증을 구분합니다.
- 일시적으로 사라지는 요소를 정답에 넣지 않으며 지연이나 세션에 따라 광고·URL·순서·선택자·정답을 바꾸지 않습니다.

## 프레임·CSS·좌표

- iframe 시험 상위 페이지≥5, 중첩 깊이 4~6, 형제 8~12개인 페이지를 포함합니다. 최상위 문서는 깊이 0이며 방문당 최상위 포함 Frame≤32입니다.
- 같은 src의 형제·같은 내부 선택자·상대 src·srcdoc·지연 프레임·바깥 조상 스타일 영향을 포함합니다. 내부 양성≥8·정상≥4입니다.
- 최상위 기준 좌표에는 프레임 border·padding·2D 평행이동을 반영합니다. iframe/조상의 회전·확대·3D·zoom은 기본 범위에서 제외합니다.
- 시간·스타일·좌표의 루트는 탐지 대상 문서입니다. 화면 밖에 놓인 audit-frame·engine-frame까지 올라가 은닉으로 판단하지 않습니다.
- 최소 4개 페이지의 시험 영역에 조상 체인 24~32단계를 구성합니다. 실제 leaf 경로와 선언한 래퍼 구간을 함께 기록합니다.
- 조상 opacity:0·누적 반투명·display:none·불투명 배경동색·투명 글자·음수 좌표·일반 요소 translate를 포함합니다. 외부 CSS·style 태그·인라인·변수·구체성·!important를 분산합니다.
- 유효 opacity 곱은 관측값입니다. 임의 임계값으로 새 기법을 부여하지 않습니다. 글꼴은 leaf의 실제 computed 값이며 조상의 0px를 자식이 덮어쓴 정상 사례를 잘못 은닉 처리하지 않습니다.
- 정상 하단 콘텐츠·접근성 안내·접힘 영역·반투명 UI는 정상입니다. viewport 밖이거나 CSS가 복잡하다는 이유로 불법 정답을 부여하지 않습니다.

## 원문·선택자·규모

- 30개 이상 반복 형제, 혼합 태그의 nth-child/nth-of-type, 클래스 없는 요소, 겹치는 클래스, 숫자·콜론·마침표·대괄호 클래스, 반복 leaf와 프레임을 포함합니다.
- 정답 선택자는 실제 문서에서 유일해야 하며 동등 CSS는 동일 노드로 인정합니다. class/id는 기법·양성 여부를 누출하지 않습니다.
- span·Text Node 분할, 직계/자식 텍스트, LF·탭·연속 공백·NBSP·분리형 한글·전각·닮은꼴·120자 초과 원문을 포함합니다. 원문 정규화·잘라내기를 하지 않습니다.
- 부모/자식 textContent 중첩을 별도 광고로 늘리지 않습니다.
- 최소 3개 페이지의 body 하위 요소는 각각 4,000~8,000개입니다. 방문 전체 문서 합계≤15,000개로 제한합니다. 의미 있는 등록부·목록을 사용하고 정답을 앞·중간·끝에 배치합니다.
- 양성 45요소 중 ceil(45/3)=15개 이상에 깊은 링크·지연·프레임·조상·반복 선택자·대규모 DOM 조건을 2개 이상 결합합니다. 최소 4개에는 4개 이상 결합합니다. 설계 수량은 20·13개이며 실측으로 확인합니다.
- 난이도 결합 수와 은닉 기법 복합 수를 별도로 집계합니다.

## 하위 호환과 정답 계약

기존 source/shared/ 엔진과 여섯 finding 필드·TOPIC·지표를 유지합니다. 새 프로필에서만 frames[]의 resource {selector,src}와 inline {selector,srcdoc:true}를 배타적으로 허용합니다. srcdoc을 가짜 리소스 URL로 만들지 않습니다.

같은 src 인스턴스를 구분하기 위해 새 프로필의 location은 각 유일한 frame.selector와 leaf를 기존 ` >>> ` 문법으로 연결합니다. 기존 무프로필과 site1 legacy의 src 기반 경로는 유지합니다. 새 프로필의 실제 문서 경계·스타일 관측을 보완하되 새 비교 엔진·집계 공식을 만들지 않습니다.

ground-truth.json은 정답이고 expected-result.json은 publicBaseUrl·고정 합성 시각으로 생성하는 정답 예시입니다. 정상은 findings에 넣지 않습니다. 채점 JSON의 참조 주석은 실제 방문 기록이나 준비된 학습셋이 아니며 FP/invalid/duplicate를 정상 라벨·TN으로 변환하지 않습니다. 주제 분류 정확도는 미지원입니다.

## 기록·완료·제외 범위

manifest.crawlPlan은 논리 페이지·예상 깊이·링크·시간표·제한을, 사례별 stressConditions는 시험 조건을 기록합니다. 설계표는 reference에만 두며 실제 측정은 tmp/verification/과 최신 VERIFICATION.md로 분리합니다.

새 컨텍스트 3회에서 entry-only BFS·전체 정답·최종 DOM·시간을 실제 측정합니다. 완전정답·누락·정상/광고기법/미해결 FP·중복·필드·유일/동등/모호 선택자·잘못된 JSON/UTF-8/BOM·쿼리·프레임·다운로드·모바일·루트/접두/단독을 확인합니다. 빌드·정적/단위·공통 회귀·재빌드 동일성과 기존 배포본/정답 바이트 보존을 확인해야 완료입니다.

클릭/스크롤 생성·로그인·form 제출·hash SPA·Shadow DOM·6~8초 생성·CSSOM만 변경·무한 애니메이션·Frame/관찰 상한 초과·고의 네트워크 오류는 기본 시험에 넣지 않습니다. 별도 확장 시험은 이번 범위에 만들지 않습니다.

실제 탐지기를 실행하지 못하면 Worker1/4·수집 범위·모델 성능은 미평가로 기록합니다. FN만으로 URL 미발견·동적 누락·탐지 실패를 단정하지 않습니다. 사이트 구현의 정확성과 크롤러 통과 여부는 별개의 결과입니다. PR 미병합 상태에서는 운영 배포 완료로 표시하지 않습니다.
