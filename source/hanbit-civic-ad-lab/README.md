# 한빛시 시민소통광장 — 불법광고 탐지 테스트 사이트

공공 웹사이트 불법광고 탐지 도구 개발 공모전 모집요강(2026년 9월)을 바탕으로 만든 프론트엔드 전용 모의 환경입니다. 주최 측의 비공개 심사 사이트를 재현했다고 주장하지 않으며, 실제 기관·거래·신청 서비스가 아닙니다.

## 실행

Node.js가 설치된 환경에서 `START_LOCAL.cmd`를 더블클릭하거나 이 폴더에서 `npm start`를 실행합니다. 패키지 설치는 필요 없습니다.

- 탐지기 진입 URL: `http://127.0.0.1:4173/index.html`
- 팀 검증실: `http://127.0.0.1:4173/lab/`
- 로컬 주소는 같은 PC에서만 접속할 수 있습니다.
- HTML을 더블클릭하는 `file://` 실행은 지원하지 않습니다. 상대 iframe, 모듈, 정답표 읽기 때문에 HTTP로 제공해야 합니다.

## 구성

47개 게시글 시나리오: 광고 요소 35개에서 필수 기법 40건, 명시적 정상 대조 12개입니다. 게시판 목록, 문화 행사, 이용 안내, 아카이브, iframe 문서는 별도로 포함됩니다.

| 기법 | 기대 건수 |
| --- | ---: |
| HOMOGLYPH | 8 |
| JAMO | 10 |
| TRANSPARENT | 12 |
| OFFSCREEN | 10 |

최종 정확한 수치는 `reference/ground-truth.json`과 `npm run check` 결과를 기준으로 삼으세요.

프론트엔드만으로 동작합니다. `dist/`가 배포 결과물이고 외부 폰트, CDN, API, 데이터베이스에 의존하지 않습니다. `scripts/serve.mjs`는 개발용 파일 서버일 뿐 제품 백엔드가 아닙니다.

- `dist/index.html`: 실제처럼 구성한 공공 게시판 진입 페이지
- `dist/board/`: 게시글, 검색·분류·페이지네이션, 쿼리별 본문
- `dist/widgets/`: 1·2단계 중첩 iframe
- `dist/archive/`: 여러 링크를 따라야 도달하는 지연 링크
- `dist/lab/`: 정답 탐색, JSON 내려받기, 자체 요소 검증, 결과 대조
- `src/fixtures.mjs`: 합성 시나리오 원본 (배포 대상 아님)
- `reference/ground-truth.json`: 위치·원문·기법 정답표
- `REQUIREMENTS.md`: 모집요강 분석과 구현 대응

## 시험 조건

1. 진입 URL 하나에서 내부 링크를 따라갑니다. `/lab/`와 정답표는 탐지 대상에서 제외합니다. 대상 페이지에는 검증실 링크가 없습니다.
2. 기준 viewport는 1440 × 1000입니다. 고정 지연은 650ms, 1,200ms, 1,600ms, 2,800ms이며 950ms 후 발견되는 링크도 있습니다. 초기 점검은 3.2초 이상 대기를 권장하되, 추후 DOM 변화 관찰로 최적화하세요. CPU/네트워크가 매우 느리면 추가 대기가 필요할 수 있습니다.
3. 권장 초기 탐색 한도는 150 URL, depth 8, 전체 1,800초입니다. 모두 사이트 자체 시험을 위한 설정이며 주최 측이 제시한 페이지 수·depth가 아닙니다. 고유 물리 파일보다 URL 수가 많은 이유는 목록 쿼리와 순환 링크입니다.
4. `?id=1024&mode=public`과 `?id=1180&mode=public`은 서로 다른 페이지입니다. 파라미터 순서만 바뀐 주소와 fragment는 중복입니다. 쿼리를 일괄 제거하지 마세요.
5. 프레임 src는 상대 경로로 제공됩니다. 결과의 iframe 경로는 절대 URL로 바꿔 기록합니다. 이 정답셋은 `findings.url`에 부모 페이지 URL을 사용합니다. 문서의 예시를 따른 자체 해석이며, 프레임 URL을 결과 URL로 사용할지에 대한 별도의 공식 해석이 나오면 갱신해야 합니다.
6. robots.txt는 대상 페이지 탐색을 허용하고 `/lab/`만 제외합니다. 대상 HTML에는 `noindex,follow`를 넣어 검색 색인에서 제외하면서 내부 링크 수집은 허용합니다. 실제 접근 통제 기능은 아닙니다.

## 검증실 사용

검증실의 ‘정답 요소 검증’은 모든 사례의 실제 DOM에서 선택자 유일성, iframe 접근, 원문 일치를 확인합니다. 탐지 알고리즘의 성공률을 대신 측정하는 기능은 아닙니다.

팀 프로그램의 `result.json`을 선택하면 브라우저 안에서 필수 필드, URL, 실제 선택자 대상, 기법을 비교합니다. 같은 요소를 가리키는 다른 CSS 선택자도 지원합니다. 동일 요소·기법의 중복은 한 건으로 합칩니다. 오류 항목, 오탐, 미탐, 재현율과 정탐 비율을 표시합니다. 공식 점수 환산식은 공개되지 않았으므로 공식 100점 점수는 만들지 않습니다. 파일의 기록 시간을 보여 줄 뿐 실제 탐지 실행 시간은 측정하지 않습니다.

‘예상 result.json’은 테스트용 정답 예시이며 실행 시간 0초의 합성 메타데이터를 가집니다. 제출용으로 사용하지 마세요. UTF-8 BOM 없이 내려받습니다. 파일 대조는 현재 접속한 사이트 주소로 생성한 결과를 대상으로 합니다.

## 변경과 배포

`src/fixtures.mjs`의 사례를 수정한 뒤 `npm run build`로 정적 페이지와 정답표를 다시 생성합니다. 공통 화면 스타일은 `dist/assets/site.css`, 하위 페이지는 `pages.css`, 검증실은 `dist/lab/`에 있습니다. 홈 화면은 정적 템플릿 역할도 하므로 `dist/`를 지우지 마세요. 생성된 게시글 본문은 빌드 시 덮어써집니다.

`npm run check`는 JavaScript 문법, 내부 파일 연결, 정답표 개수와 대상 파일을 점검합니다. 브라우저에서 ‘정답 요소 검증’도 실행하세요.

사이트 번호·이름·배포 경로·기본 포트는 저장소의 `source/sites.json`에서 관리합니다. 빌드는 `lab/`을 제외한 생성 파일을 등록된 `test-site-N/`으로 자동 동기화하고 루트 목록을 갱신합니다. 검사는 소스 사례와 정답표, 배포 파일의 일치도 확인합니다. 이 프로젝트는 공통 관리 파일과 함께 사용하며, 저장소 루트의 `node source/manage.mjs build 1`·`check 1`로도 실행할 수 있습니다. `PORT`와 `STATIC_ROOT`로 로컬 서버 설정을 변경할 수 있고 오류 결과 생성기는 `ENTRY_URL`로 시험 주소를 지정할 수 있습니다.

일반 정적 호스팅에는 `dist/` 내용만 업로드하면 됩니다. 루트 도메인뿐 아니라 하위 경로 배포도 상대경로로 지원합니다. SPA fallback이나 서버 rewrite는 필요하지 않습니다. `view.html`과 `list.html`은 브라우저에서 쿼리를 읽으므로 쿼리 전달을 유지하세요.

정답 비공개 평가가 필요하면 배포 복사본에서 `lab/`을 제외하고 `reference/`를 시험 담당자가 별도로 보관하세요. 현재 검증실은 비밀번호로 보호되지 않으며, 대상 페이지에서 링크하지 않는 방식으로만 구분합니다. 정답을 모르는 상태의 시험에는 URL을 추측해 검증실을 읽지 않도록 평가 규칙을 정하세요.

저장소 전체를 정적 서버에서 제공할 때 `source/hanbit-civic-ad-lab/dist/lab/` 검증실은 같은 저장소의 `test-site-1/`를 검사 대상으로 사용합니다. `dist/`만 로컬에서 제공하면 기존처럼 로컬 `index.html`을 기준으로 검사합니다.

이 버전은 크롤링 정확성과 재현성에 중점을 둡니다. 대규모 성능 측정용 수천 페이지, 교차 출처 iframe, 로그인, 서버 리다이렉트, CAPTCHA, 이미지 OCR, Shadow DOM은 포함하지 않습니다. 30분은 목표 실행 시간이 아니라 상한입니다.
