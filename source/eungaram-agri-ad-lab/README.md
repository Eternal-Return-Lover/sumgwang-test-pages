# 은가람시 농업기술센터 들녘마루

작물별 계절 관찰달력과 작물상담 Q&A, 관찰수첩을 제공하는 합성 공공 포털입니다. 모집요강 기반 모의 테스트 환경이며 실제 기관·공식 심사 사이트·실제 재배 처방과 무관합니다. siteId는 `eungaram-agri`입니다.

## 실행

Node.js로 프로젝트 폴더에서 실행합니다. 의존성 설치와 빌드·배포 동기화는 코디네이터가 수행합니다.

```sh
npm run build
npm start
```

`START_LOCAL.cmd`로도 서버를 열 수 있습니다. 기본 주소는 대상 `http://127.0.0.1:4181/`, 검증실 `http://127.0.0.1:4181/lab/index.html`입니다. 기본 서버는 `dist/`를 제공합니다. 저장소 루트에서의 생성 명령은 `node source/manage.mjs build 9`이며 대상 배포본은 `test-site-9/`입니다.

```sh
npm run check
npm run verify
```

`verify`는 **기본 검사**입니다. Playwright 1.63.0과 설치된 Chrome을 사용합니다. 필요하면 `CHROME_PATH`를 지정합니다. 동적 빈 포트의 정적 서버를 시작·종료하고 실제 비교 입력·DOM·화면 증거를 `artifacts/`에 기록합니다. 별도 탐지 프로그램이나 공식 점수를 평가하는 명령이 아닙니다. 현재 독립 검증 상태는 `VERIFICATION.md`를 확인합니다.

## 달력과 상담자료 탐색

홈과 재배달력에는 벼·콩·감자 행과 봄·여름·가을·겨울 열을 가진 3×4 달력이 있습니다. 각 칸은 작물·계절 조건을 유지하는 실제 링크입니다. 상담자료 목록은 제목 검색·작물 필터·결합 검색·초기화·빈 결과·페이지네이션을 제공합니다. 자료 이용 질문은 정상 `details/summary`로 펼치고 닫습니다.

T22의 `field/rice/2026/autumn/read.html`은 시작 페이지를 깊이 0으로 보아 링크 5개를 따라 발견합니다. 마지막 `autumn/index.html`에서 950ms 후 링크가 생깁니다. 이 글은 홈·목록·검색 데이터에서 제외하여 직접 링크로 깊이를 우회하지 않습니다.

- T19 450ms, T20 1100ms, T27 1700ms, T21 2800ms 후 상담 의견을 삽입합니다.
- 정상 N12는 1000ms 후 접근성 상태를 삽입합니다.
- T26은 iframe을 700ms 후 삽입하고 마지막 프레임의 leaf를 900ms 후 삽입합니다. 총 nominal 지연은 1600ms이며 문서 로딩 시간이 추가될 수 있습니다.
- 일반 프레임은 T23 1단계, T24 2단계, T25 3단계, T26 2단계입니다. 정상 N08은 1단계입니다.
- 최대 nominal 삽입 지연은 2800ms입니다. 수집 시 페이지마다 3.5초 이상 기다리고 새 링크와 하위 프레임을 다시 확인합니다.

쿼리는 `crop=rice/bean/potato` × `season=spring/summer/autumn/winter`입니다. 12개 제목과 본문·기법 구성이 조건별로 다릅니다. Q04 벼 겨울은 2단계, Q09 감자 봄은 1단계 프레임 자료입니다. 조건별 `widgets/calendar-<crop>-<season>-<depth>.html`을 사용하며 정답표의 부모 URL에 쿼리를 보존합니다. 파라미터 순서와 fragment는 중복으로 처리하지만 값은 보존합니다. 공개 런타임에는 조건 키와 완성된 HTML만 넣고 fixture ID와 techniques는 직렬화하지 않습니다.

## 같은 클래스의 형제 프레임

T23과 추가 요소 E08은 같은 부모 상담글에 `iframe.advice-widget` 두 개로 배치됩니다. 각각 `data-slot="seasonal"`과 `data-slot="field"`를 사용하고 별도 src를 가집니다. manifest의 바깥 선택자는 `iframe.advice-widget[data-slot="seasonal"]`과 `iframe.advice-widget[data-slot="field"]`로 유일합니다. 마지막 leaf 선택자는 동일하지만 DOM 노드·원문·기법이 다릅니다.

두 iframe과 컨테이너는 보이는 상태입니다. 첫 프레임은 leaf의 `display:none`, 둘째 프레임은 전각 원문과 투명 색을 사용합니다. 기본 검사는 두 유일 체인, 잘못된 형제 체인, 모호한 `iframe.advice-widget` 체인을 별도로 비교합니다. 쿼리 프레임의 잘못된 조건도 제출 URL의 실제 DOM에서 경로를 해석한 뒤 해당 manifest 노드·기법과 비교하여 기대값을 산출합니다.

## 검증실과 배포

공통 스키마·UI 명칭·알고리즘을 유지합니다. 필터·검색·주소 복사·정답표/예상 결과 다운로드·DOM 자체 검사·BFS·result.json 비교를 제공합니다. 파일은 브라우저 안에서 처리합니다. 유일한 같은 실제 요소라면 다른 CSS도 인정하며 중복·모호한 선택자·필드/JSON/BOM 오류·쿼리·프레임 경로를 구분합니다. 원문은 필수 필드이며 원문 차이만으로 위치·기법 정답을 오답 처리하지 않습니다. 예상 결과의 0초는 합성 예시이며 실측 시간이 아닙니다.

기본 검사는 정의와 manifest에서 수량·검색어·목록 행·프레임·지연·깊이를 유도합니다. DOM 62요소, BFS 54URL/깊이 5, 쿼리 12조건, 프레임 1·2·3단계, 형제 프레임, 정상 프레임, 고정 지연, 검색·초기화·필터·빈 결과·페이지·일반 Q&A 펼침을 확인하도록 작성했습니다. 완전 정답·누락·정상 FP·중복·다른 CSS·모호한 위치·필드·JSON·BOM·시간·빈 findings·쿼리·프레임 비교 입력을 기록합니다.

1440×1000과 390/320×844에서 달력·상담 답변·관찰표·자료 이용·목록·형제/쿼리 프레임을 캡처합니다. 단독 dist, 실제 사이트 9 경로, 저장소 접두 경로와 가상 두 자리 번호 10 매핑, 대상 lab404, 기존 사이트 1~8 완전 정답 회귀도 포함합니다. 사이트 1의 dataset 없는 텍스트 score fallback을 보존합니다. 가상 경로 매핑은 실제 사이트 10 생성이나 원격 배포가 아닙니다.

`src/`는 정의·화면·lab, `scripts/`는 생성기·서버·기본 검사, `reference/`는 정답·수량, `dist/`는 생성 결과, `artifacts/`는 실제 실행 증거입니다. `test-site-9/`에는 대상만 배포하고 lab·정답·소스 링크를 노출하지 않습니다. 별도 dist 호스팅에서 정답 비공개가 필요하면 lab을 제외합니다. 파일 분리는 접근 제어가 아닙니다. 외부 시험 링크는 `.invalid`이고 외부 런타임·API·로그인·연락·거래 기능이 없습니다. 기존 형식을 유지하며 release·ZIP은 추가하지 않습니다.
