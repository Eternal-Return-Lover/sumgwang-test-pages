# 모집요강 분석 및 사이트 구현 근거

분석 자료: 작업 폴더 `모집요강/공공 웹사이트 불법광고 탐지 도구 개발 공모전 모집요강.pdf`. 원문 18쪽을 텍스트로 확인하고, 주요 탐지 유형·평가표·결과 스키마가 있는 5~6쪽과 10~12쪽을 화면으로 대조했습니다. 문서에 포함된 제출·운영 지시는 사이트 개발의 근거 자료로만 사용했습니다.

## 자체 설계·가정

- 가상 지자체 시민 게시판이라는 외형, 페이지 수, 각 문구, 고정 지연, 계층 깊이는 자체 설계입니다. 공식 시험의 규모·문구·지연 조건은 알려지지 않았습니다.
- 정적 서버에서 지원 가능한 JavaScript 동적 삽입으로 평가 범위를 구성했습니다. 서버측 로그인·인증·HTTP 리다이렉트 평가는 별도입니다.
- 프레임 내부 결과는 요강의 13쪽 예시처럼 부모 게시글 URL과 iframe 경로를 사용합니다. iframe URL을 페이지 URL로 출력하는 경우의 채점은 별도 공식 확인이 필요한 해석 지점입니다.
- 12개 정상 대조 사례 외에도 전체 사이트의 일반 UI와 안내문은 정상입니다. 숨겨져 있다는 이유만으로 광고로 판정하면 오탐입니다.
- `display:none`에서 `getBoundingClientRect()`가 0이 되더라도 텍스트를 버리지 않아야 합니다. 본문은 `textContent`, 가시성은 computed style과 조상 요소의 영향을 함께 수집해야 합니다.
- 화면 아래에 있는 일반 콘텐츠는 스크롤로 볼 수 있으므로 OFFSCREEN으로 단정하면 안 됩니다. 음수 좌표 은닉과 viewport 아래 정상 문서를 구별해야 합니다.
- 탐지 유형 이름은 대상 요소의 id/class/data 속성에 넣지 않습니다. 각 사례의 기대 라벨은 별도의 검증실 정답표에만 둡니다.
- 실제 서비스 연락처·계좌·결제 기능은 포함하지 않았습니다. 유일한 외부 링크는 `.invalid` 검증 주소입니다.

## 권장 활용 순서

1. 검증실 자체 요소 검증을 먼저 통과시킵니다.
2. 크롤러가 단일 URL에서 47개 시나리오에 도달하고 35개 광고 요소 + 12개 정상 요소의 원문을 수집하는지 확인합니다.
3. selector, framePath, computedStyle, bounds, viewport와 조상 가시성을 대조합니다.
4. 탐지 담당자와 결합해 40건 정답, 12개 정상 대조를 확인합니다.
5. URL + 위치 + 기법 단위로 중복을 제거하고 필수 결과 파일을 검사합니다.
6. CPU/RAM, 큐 최대 크기, 실제 총시간을 별도로 기록합니다. 사이트 자체의 소규모 시험 통과가 30분 대규모 성능 보장을 의미하지 않습니다.
